# 工程表 Webアプリ（実装フェーズ・第一弾）

北条工場 工程表プロジェクトの、プロトタイプ（Artifact）から実コードへの最初の移植です。設計ドキュメント8章の段階的実装ステップのうち、ステップ1〜3（データモデル・モックデータ・静的UI）に相当します。

## 開発環境の準備

Node.js（18以降推奨）が必要です。Visual Studio（または Visual Studio Code）でこのフォルダを開いたら、ターミナルで以下を実行してください。

```
npm install
npm run dev
```

`npm run dev` を実行するとローカルサーバーが起動し、表示されるURL（通常 http://localhost:5173 ）をブラウザで開くと動作確認できます。コードを編集すると自動的に画面が更新されます（Vite の HMR）。

本番用ビルドを作る場合：

```
npm run build
```

`dist/` フォルダに静的ファイル一式が出力されます。型チェックも同時に走るので、型エラーがあればここで失敗します。

## 技術構成

- **Vite + React + TypeScript**：設計ドキュメント9章で保留になっていた「React か Vue か」は、今回 React を採用して進めています（エコシステムの大きさを理由に推奨し、そのまま実装しました）
- 外部ライブラリはほぼ使わず、素のReact（useState/useContext）で状態管理しています。将来的にルーティングやAPI通信が増えてきたら、そのタイミングでライブラリ追加を検討してください
- 現時点ではバックエンド・mcframe連携・WebSocketは未実装です（設計ドキュメント1章・5章）。データはすべて `src/data/mockJobs.ts` のモックです

## 画面構成

起動すると必ず「メインメニュー」から始まり、そこから「工程表一覧」「設定」に進みます。工程表（ボード）は用途ごとに何個でも作成でき、それぞれ完全に独立したデータ（オーダー・工程・表示設定）を持ちます。

```
メインメニュー
├── 工程表一覧 … 既存ボードを開く／名前変更／削除、「＋新規作成」で空のボードを作成してそのまま開く
│   └── （各ボード）ライン工程表／オーダー進捗表の2タブ＋右上の歯車アイコンから設定画面（設計ドキュメント3-8参照。2026-09-23変更）
│       └── 設定画面 … マスタ設定／連携設定／稼働計画設定／オーダー行表示項目／積み上げ工数・負荷率設定／書き戻し設定（設計ドキュメント3章・2章・7章・1-3章）
├── 俯瞰ビュー … 全工程表を横断した負荷率サマリー（設計ドキュメント3-9。2026-09-23追加、同日V2改修）
└── 設定 … 画面配色（端末の設定に合わせる／ライト／ダーク）。今後ここに設定項目を追加していく予定
```

以前はマスタ設定・連携設定・稼働計画設定がライン工程表・オーダー進捗表と並ぶタブとして常時表示されていましたが、情報量が多く煩雑という指摘を受け、これらとオーダー進捗表内にあった「オーダー行表示項目」「積み上げ工数・負荷率設定」を1つの設定画面にまとめました（2026-09-23）。トップバー右上の歯車アイコンから開き、「← 工程表に戻る」で元の画面（開いたときに見ていたライン工程表／オーダー進捗表）に戻ります。

**俯瞰ビュー**（2026-09-23追加・同日V2改修）は、工程表ごとに完全に独立しているデータを横断して負荷率を比較できる画面です。画面上部に横一本の日付軸があり、その下に工程表ごとの行が縦に並びます。軸の粒度は「日／月／年」で切り替えられ（既定は月）、「年」表示のときは「暦年／年度（4月始まり）」も切り替えられます。◀／▶／「現在」で表示期間を移動します。各工程表の行は最初は「全体」の集計だけを表示しており、行をクリックすると工程別（ライン別・資源別・得意先別にも切替可）の内訳が展開されます。「＋ 工程表を合体」から2件以上の工程表を選んで合算した負荷を1つの行として見ることもでき、作成した合体はブラウザを閉じても保持されます（「解除」で削除。元の工程表自体には影響しません）。行や展開エリアから「この工程表を開く→」でそのままライン工程表に移動できます。

初回起動時のみ、これまでのプロトタイプで確認していた北条工場1〜6のサンプルデータ（ライン・資源マスタ含む）が「北条工場サンプル」という1件目のボードとして自動的に用意されます。新規作成したボードはオーダー・ライン・資源のすべてが空の状態から始まるので、まず「マスタ設定」タブでライン・資源を登録してください。

「マスタ設定」タブでは、その工程表専用のライン一覧・資源一覧を追加・名前変更・削除できます（工程表ごとに完全に独立しており、他の工程表には影響しません）。使用中（いずれかの工程から参照されている）のライン・資源は削除できません。

各ライン・資源には任意で「ラインCD」「資源CD」を設定できます（2026-09-23追加）。これは連携設定タブで取り込む工程データ・ライン対応マスタ・資源マスタの「ラインCD」「資源CD」列とこの工程表のライン・資源を紐付けるためのものです。設定しておくと、連携設定タブの③結果プレビューで、そのコードがこの工程表のどのライン・資源として解決されているか（未登録の場合は「⚠ 未登録」）を確認できます。未設定の場合は名前が一致するかで判定します。ラインCDはシステム移行などで旧CD・新CDが混在する場合を想定し、1つのラインに複数のコードを登録できます（チップ形式のUIで追加・削除）。資源CDは1つの資源につき1コードのみです。

「連携設定」「稼働計画設定」タブについては下記「連携設定／稼働計画設定タブについて」を参照してください。

## プロトタイプ（Artifact）との対応

見た目・機能は `FactorySlot 工程表` Artifact（Version 10）とほぼ同一です。以下は実装済みです。

- ライン工程表／オーダー進捗表の2画面切替
- ライン工程表の横表示／縦表示切替（縦表示は時間軸を縦にし、バー内に品名を追加表示できます。2026-09-22追加）
- 行の非展開／展開（アコーディオン）表示
- フリーワード検索＋複数条件AND絞り込み（得意先／ライン／資源／工程名／状態／特注No等）
- オーダー行の表示項目設定（得意先／品目CD／品名／特注No／納期／予定数量／予定工数／進捗）
- 表示期間（2週間〜1年）
- 積み上げ工数・負荷率のサマリ行（休暇・応援イベントによる基準工数の増減を反映）
- 工程の日程調整（この工程のみ／オーダー全体をスライド、詳細シート内の±1日／±1週ボタン）
- 工数の時間／分表示切替

さらに、詳細シートを開かなくても調整できる補助手段として以下を追加しています（設計ドキュメント3-4-1参照）。

- Ganttバーをクリック → オーダー全体を選択、ダブルクリック → その工程のみを選択（グリッド上部の帯に選択状態を表示）
- 選択中のバーはそのままドラッグしてシフト可能（OrderScreenは1日単位、LineScreenは15分単位にスナップ）
- 選択中に←→キーでも同じ単位でシフトできる（Escキーで選択解除）
- 選択中に詳しい内容を見たい／実績を編集したい場合は、帯の「詳細」ボタンから従来の詳細シートを開ける
- 詳細シートには「もう片方の画面で見る」ボタンがあり、ライン工程表で見ている工程のオーダーをオーダー進捗表で確認したり、逆にオーダー進捗表で見ている工程のラインをライン工程表で確認したりできます（2026-09-23追加。選択中の工程・該当行の展開・表示期間の移動が自動で連動します）

## 連携設定／稼働計画設定タブについて（2026-09-22追加）

当初は別々のArtifactプロトタイプ（`FactorySlot 連携設定`／`FactorySlot 稼働計画設定`）としてのみ存在していた2つの設定機能を、本体アプリのタブとして統合しました。

**連携設定タブ**（設計ドキュメント2章）：mcframe出力の列マッピング・結合（JOIN）ルールを設定する画面です。①ファイルマッピング／②結合設定／③結果プレビューの3画面で構成されます。実際のファイル取り込み（バックエンドでのCSV読み込み・自動適用）はまだ実装していないため、③結果プレビューはサンプルデータに対する確認用です。設定はボード単位で保存されますが、他のタブと違って自動保存ではなく「設定を保存」ボタンを押すまでは反映されません。

**稼働計画設定タブ**（設計ドキュメント7章）：①持ち工数／②イベント登録／③条件フロー・実行／④カレンダーマスタの4画面で構成されます。

- **①持ち工数・②イベント登録は実データとして使われます**。ここで設定した曜日別の基本工数・応援や休暇のイベントは、ライン工程表・オーダー進捗表の「積み上げ工数・負荷率」の基準工数計算にそのまま反映されます（ボードごとに独立）
- **①持ち工数の対象単位はライン別／資源別／工程別／品目別の4種類です**（品目別は2026-09-23追加）。資源別／工程別／品目別の対象アイテムは、マスタ設定・実データに加えて連携設定タブの結合結果からも重複除去して集められます（2026-09-22追加）。連携設定タブで「設定を保存」した内容が反映されるため、資源・工程・品目の選択肢を増やしたい場合は先に連携設定タブ側でマッピングを保存してください
- **候補に無い対象は、その場で名前を決めて追加できます**（2026-09-23追加。「任意の項目を追加」欄。全4単位に対応）。品目別を選んでいるときはCSV取り込み（ファイルアップロード／テキスト貼り付けの両方）にも対応しており、件数が多い品目もまとめて登録できます。追加した項目には「追加項目」バッジが付き、不要になれば行の削除ボタンで消せます
- **一度設定した持ち工数・イベントの値は、読み込み時に対象の工程や資源が無くなっていても保持されます**（2026-09-23追加）。マスタ設定の変更や連携設定のマッピング変更で候補一覧から消えた対象は、値を保存したままシートに「未検出」バッジ付きの行として残り続け、引き続き編集・削除ができます
- **③条件フロー・実行は、このボードの実際の工程データに対してシミュレーションを実行できます**が、実行結果を工程表へ書き戻す処理は未実装です（確認用にとどまります）
- **④カレンダーマスタは設定・プレビュー画面のみです**。ライン工程表・オーダー進捗表の週末網掛けなどは引き続き固定の土日休みパターンを使っており、ここで登録した特別稼働日・特別休業日はこのタブ内のプレビューにのみ反映されます

## 書き戻し設定タブについて（2026-09-23新設）

工程調整（ドラッグ・矢印キー・±1日/±1週ボタン）の結果をmcframeへ反映するための機能です。mcframe側には工程データを直接書き込む手段（API・取込バッチ）が無く画面からの手入力のみのため、工程表アプリからmcframeへ自動的に反映することはできません。代わりに、既に運用中のRPAがmcframe画面への入力に使うCSVを出力します。

- 工程調整を行うと、対象の工程に「書き戻し待ち」の印が付きます（詳細シートに↩バッジで表示）。書き戻し設定タブの「出力対象」一覧にはこの印が付いた工程だけが並びます
- 「CSVを出力」を押すとダウンロードされ、同時に出力した工程の「書き戻し待ち」は解除されます（再度調整すればまた対象に戻ります）
- 出力する列（項目・見出し文字列・日付書式・並び順）と文字コード（Shift-JIS／UTF-8）はボードごとに自由に設定でき、「設定を保存」を押すまでは列構成の変更は反映されません（CSV出力自体は保存前の設定でも実行できます）
- ラインCD・資源CDは、この工程表アプリ内部の表記（ライン名・資源名）からマスタ設定の対応表を使って変換して出力します

## 表示固定・選択中行列ハイライトについて（2026-09-24新設）

オーダー進捗表・ライン工程表（横表示）で、Excelのウィンドウ枠固定と同様の表示固定に対応しました。

- **上部固定**：オーダー進捗表では「積み上げ工数・負荷率」の負荷サマリと日付軸ヘッダーがまとめて上部に固定され、下の方の工程を調整する間もスクロールで隠れません
- **左端固定**：オーダー・ライン・資源のラベル列（一番左の列）が横スクロール中も常に見える位置に固定されます（ライン工程表・縦表示の資源ラベルも同様に固定されています）
- **選択中の行・列のハイライト**：工程（ジョブバー）を選択すると、その工程を含む行がうっすら着色され、その工程の日程にあたる日付列（日付軸ヘッダー・負荷サマリの該当セル）に枠線が付きます。固定表示された負荷サマリ上でも、選択中の工程がどの日付に乗っているか一目でわかります
- 表示固定は`.gridscroll`（工程表グリッドの外枠）に高さの上限（65vh）を設けて実現しているため、工程表グリッド自体がその枠内で縦横にスクロールする形になります（ツールバー・フィルタ・統計等はページ側に固定されたまま動きません）

## 部門内共有サーバー（2026-09-24新設・準備中）

複数人でリアルタイムに工程表を同期するための部門内共有サーバーの土台（`server/`ディレクトリ）を用意しました。現時点ではアプリ画面からはまだ呼び出しておらず（アプリは従来どおり`localStorage`だけで動作する`LocalBoardProvider`を使用）、サーバー・クライアント双方のコードと動作検証のみ済んでいる段階です。設計の背景・判断理由は`gantt_design_draft.md`の5章（特に5-3-1「サーバー変更のハードルを下げるための設計判断」・5-6）を参照してください。

- `npm run server` … 部門内サーバーを単独プロセスとして起動します（既定ポート8787、DBは`server/data/kouteihyou.sqlite3`。`PORT`・`DB_PATH`環境変数で変更可）
- `npm run typecheck:server` … サーバー側コード（`server/`）の型チェック（アプリ本体のビルド・`tsc -b`とは別枠）
- サーバーのデータファイル（`server/data/`・`*.sqlite3*`）は`.gitignore`対象です。サーバー役のPCを乗り換える際は、このファイル1つをコピーすれば工程データ・監査ログを引き継げます

## 自動工程調整について（2026-09-24新設、同日UI追加）

持ち工数超過の検出・移動先探索・実際の工程表への反映は、稼働計画設定タブの「③条件フロー・実行」に加えて、ライン工程表・オーダー進捗表の各画面上部にある「自動工程調整」パネル（クリックで開閉）からも直接実行できます。

- 画面上の「自動工程調整」パネルでは、対象期間（から・まで）の指定→「▶自動調整を実行」→移動プランのプレビュー→「この内容で反映する」までを、設定画面に移動せずその場で行えます。対象工程の絞り込み・優先順位ルール・制約条件そのもの（下記）は設定画面側でのみ設定するため、パネル内の「条件・優先順位の詳細設定を開く →」から稼働計画設定タブの「③条件フロー・実行」を開いた状態へ直接遷移できます
- ④カレンダーマスタの固定稼働曜日・例外日は、持ち工数の計算・自動調整・ライン工程表／オーダー進捗表の非稼働日網掛けに実際に反映されます（俯瞰ビューの共通日付軸ヘッダーの網掛けのみ、複数ボードを横断する都合上、固定の土日パターンのまま）
- ⑤得意先優先度タブで、得意先ごとの優先順位（上ほど優先度が高い）を設定できます。③条件フローの「得意先優先度順」ルールと、自動調整の実行時にこの順位を使います
- 自動調整の実行は、①〜③の条件（対象工程の絞り込み・優先順位ルール・制約条件）と指定期間から、持ち工数超過が起きている工程を、優先順位の低いものから順に、同じライン／資源／工程／品目内の空いている直近の稼働日（最大60日先まで）へ移動するプランを作成し、内容を確認したうえで「この内容で反映する」ボタンで実際の工程表に反映します。反映された工程は書き戻し設定タブの出力対象（CSV書き戻し）にも自動的に含まれます
- 未実装の割り切り：ライン変更（`lineEligibility`制約）は、品目⇔対応ラインマスタが未整備のため対象外です（同じ単位内での日付シフトのみ探索します）

## 手動調整パターンの検知・提案について（2026-09-26新設）

同じ得意先・ライン・資源・工程の組み合わせで、同じ向き（前倒し／後ろ倒し）の手動調整（オーダー進捗表での±日シフト）が繰り返されると、稼働計画設定タブの「③条件フロー・実行」に「手動調整のパターンを検知しました」という提案パネルが表示されます。

- 外部のAI（LLM API）は使っていません。手動調整の履歴（このボードの`localStorage`に新設）を集計する、ルールベースの検知です（既定では3回以上の繰り返しで検知）
- 検知対象はオーダー進捗表での日単位シフトのみです。ライン工程表の分単位シフトは対象外です（自動調整の実行は日単位でしか工程を動かさないため）
- 提案の「得意先優先度に反映する」ボタンを押すと、その得意先が⑤得意先優先度タブの一覧へ反映されます（前倒しパターンなら優先度を上げる＝先頭へ、後ろ倒しパターンなら優先度を下げる＝末尾へ）。反映後は⑤タブでいつでも確認・並べ替え・削除できます
- 「✕」でその提案を消せます（履歴自体は消えません。次回別の組み合わせが閾値に達すれば改めて提案されます）

## Electronパッケージング（デスクトップアプリ化、2026-09-25新設）

`npm run dev` でブラウザから見るだけでなく、Mac用のデスクトップアプリ（`.app`／`.dmg`）としてビルドできるようになりました。設計ドキュメント5章（特に5-3-1・5-7）のステップ3にあたります。アプリ名は「工程表」、Bundle IDは `com.takedanaoya.kouteihyou` です。

### 必要な準備（初回のみ）

- **Xcode Command Line Tools**：`xcode-select --install`（ネイティブモジュール`better-sqlite3`の再ビルドに必要）
- `npm install`（`electron`・`electron-builder`・`esbuild`・`@electron/notarize`が新しく追加されています）

### 開発中の動作確認

ターミナルを2つ使います。

```
# ターミナル1：Viteの開発サーバー
npm run dev

# ターミナル2：Electronでそれを開く
ELECTRON_START_URL=http://localhost:5173 npm run electron:dev
```

コードを編集すると（Vite側のHMRで）画面が自動更新されます。

### 配布用ビルド

```
npm run electron:build
```

内部では「①`npm run build`でWeb本体をビルド → ②`npm run build:server-bundle`で部門内共有サーバーをCommonJSバンドルに変換 → ③`electron-builder --mac`でパッケージング」の順に実行されます。出来上がった `.app`／`.dmg`／`.zip` は `release/` フォルダに出力されます（Viteの`dist/`とは別フォルダです）。

- **コード署名**：Keychainに有効な「Developer ID Application」証明書があれば、electron-builderが自動的に検出して署名します（Apple Developer Program登録済みであれば通常は追加設定不要です）
- **公証（notarization）**：以下の3つの環境変数をすべて設定してから`npm run electron:build`を実行すると、署名後に自動で公証まで行われます。3つとも未設定の場合は公証をスキップし、ローカル確認用の署名済みビルドが作られます（3つのうち一部だけの設定はエラーになります。設定ミスに気づかず配布するのを防ぐためです）

  ```
  export APPLE_ID="（Apple IDのメールアドレス）"
  export APPLE_APP_SPECIFIC_PASSWORD="（そのApple IDで発行した『App用パスワード』）"
  export APPLE_TEAM_ID="（Apple Developer ProgramのチームID）"
  npm run electron:build
  ```

  「App用パスワード」は [appleid.apple.com](https://appleid.apple.com/) の「サインインとセキュリティ」→「App用パスワード」から発行できます（Apple IDのログインパスワードとは別物です）。

- ビルドは実行したMac自身のCPUアーキテクチャ（Apple Silicon／Intel）向けに作られます。両アーキテクチャ分を1つにまとめた「universal」ビルドは、ネイティブモジュールの結合が複雑になるため今回は見送りました。異なるアーキテクチャのMacで使う場合は、そのMac上で改めて`npm run electron:build`を実行してください

### 「サーバーとして動作」モード（5-3-1）

部門内共有サーバー（`server/`）を、別のNode.jsプロセスとして起動するのではなく、このElectronアプリ自体に組み込んで動かせます。アプリのメニューバー「動作モード」→「このMacをサーバーとして動作させる」にチェックを入れる（アプリの再起動が必要。ダイアログから即座に再起動できます）と、次回起動時からアプリ内でWebSocketサーバー（既定ポート8787）が立ち上がります。サーバーの設定・SQLiteデータファイルは、このMacのアプリデータフォルダ（`~/Library/Application Support/工程表/`）に保存されます。サーバー役のPCを乗り換える際は、このフォルダの`kouteihyou.sqlite3`をコピーし、新しいPCにも同じアプリをインストールして同じ設定をONにするだけで済みます（5-3-1参照）。

まだ実装していないもの：ボードごとに「スタンドアロン／サーバー接続」を切り替える画面内UI、接続先アドレスの設定、監査ログの閲覧画面（設計ドキュメント5-4のステップ5）。現時点で追加したのは、あくまで「このMac自体をサーバー役にするかどうか」というアプリ単位の設定です。
